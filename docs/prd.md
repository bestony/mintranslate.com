## 1. 文档说明

### 1.1 目的

本文档定义 MinTranslate 的产品定位、功能范围、优先级与功能约束，作为设计、开发与验收的唯一依据。

### 1.2 需求来源

本节需求来自对竞品 **Google 翻译**（`https://translate.google.com`）的真实操作体验与逐项拆解，实测时间：2026-10-02。

实测覆盖的操作路径：

| 序号 | 操作 | 观察结果 |
| --- | --- | --- |
| 1 | 打开默认页（`sl=auto&tl=zh-CN&op=translate`） | 进入「文本翻译」，源语言为「检测语言」，目标语言为「中文（简体）」 |
| 2 | 输入英文长句 | 自动识别为「英语 - 检测到的语言」，结果流式返回，按句拆分为多行 |
| 3 | 打开设置菜单 | 语速设置为「正常 / 慢 / 更慢」，每档带「测试」播放按钮 |
| 4 | 展开「更多源语言」 | 弹出带搜索框的语言列表，选项按中文拼音排序，共 200+ 项 |
| 5 | 依次进入图片 / 文档 / 网站翻译 | 各自的独立上传与输入形态；网站翻译对非法输入提示「输入内容必须是格式正确的非空网址」 |
| 6 | 点击交换源/目标语言 | 源、目标语言互换，原文与译文同时互换，页内文案随之变化 |
| 7 | 输入中文并切换目标语言为英语 | 目标语言为英语时，原输入区额外出现「文字翻译模型」「输入工具」入口 |
| 8 | 打开「文字翻译模型」菜单 | 提供「高级（借助 Gemini，准确性更高）」与「经典」两个模型档位 |
| 9 | 打开手写输入面板 | 提供画板、标点符号快捷插入、「多语种」标识 |
| 10 | 点击「保存翻译」 | 弹出「登录即可查看已保存的译文」模态框，未登录不可保存 |
| 11 | 点击「复制译文」 | 提示「译文已复制」 |
| 12 | 点击「分享此译文」 | 提供「电子邮件」（`mailto:`，正文含译文）与「X」（`twitter.com/intent/tweet`） |
| 13 | 点击「请对此翻译评分」 | 展开「翻译质量很棒 / 翻译质量很差 / 提出修改建议」，修改建议可进入可编辑替换文本界面 |
| 14 | 访问「历史记录」 | 未登录被重定向到 Google 登录页 |

## 2. 产品定位

### 2.1 一句话定义

MinTranslate 是一个**面向个人的自托管 AI 翻译工作台**：以文本翻译为核心，逐步覆盖图片、文档与网站翻译，支持多模型（OpenAI / Anthropic / Gemini / Ollama）与本地部署。

### 2.2 目标用户

| 用户画像 | 核心诉求 |
| --- | --- |
| 个人开发者 / 技术用户 | 阅读英文文档、报错、论文，希望结果留在本地、可换模型 |
| 内容与运营人员 | 批量翻译文案、文档，需要术语一致、可保存与复用 |

### 2.3 与竞品的差异化

1. **模型可替换**：不绑定单一厂商，用户自带 Key 或走本地 Ollama。
2. **数据可控**：历史记录与语料默认存本地，无需账号、无需登录。
3. **可编程**：提供 API 与 MCP 接入，方便被其他 Agent 调用。
4. **术语表与翻译记忆**：把「一致性」作为一等公民，而非附加功能。
5. **无账号、无云同步**：单机单用户即可完整使用，不引入注册、登录与云端数据库。
6. **聚焦个人场景**：不做团队协作、成员管理、共享语料与配额分配，避免为协作能力牺牲单机体验。
7. **BYOK 浏览器直连**：用户自带 Endpoint / Model / API Key，密钥只存在浏览器，项目方不承担任何 API 成本与密钥托管责任。
8. **零后端可部署**：产物为纯静态资源，可直接托管在任意静态站点，无需服务器与数据库。

### 2.4 非目标（本阶段明确不做）

- 不做语音同传 / 实时会议字幕。
- 不做浏览器的整站代理式翻译插件（网站翻译仅做「按 URL 抓取 + 译文并排展示」）。
- 不做社区众包式翻译质量共建。
- **不做账号体系与云同步**：不提供注册、登录、多端同步；全部用户数据仅存本地。
- **不做团队协作能力**：不提供成员管理、团队空间、共享语料、审批流与配额分配，产品定位为单机单用户。
- **不引入服务端密钥托管**：不提供平台方 API Key、不做用量代付、不代理任何模型请求（除非用户显式启用 Workers 兜底，见第 7 章）。
- **不引入独立 OCR 引擎**：图片文字识别由多模态大模型承担，不单独接入 Tesseract / Google Vision 等 OCR 服务。
- 不承诺覆盖 Google 的全部 200+ 语种，一期聚焦下列 12 种语言（见 `FR-LANG-02`）。

## 5. 功能约束详情

### 5.1 文本翻译（P0）

#### FR-TEXT-01 实时翻译

**描述**：用户输入文本后自动翻译，无需手动点击按钮。

**约束**：
- 触发方式：输入停止后 **600ms 防抖**触发；用户按 `Cmd/Ctrl + Enter` 立即触发。
- 输入为空或仅空白字符时，不发起请求，结果区恢复空态。
- 结果必须**流式渲染**：请求开始后立即展示「翻译中」占位，首个 token 到达时间目标 < 1.5s（P95，正常网络）。
- 同一输入的重复请求必须可取消：新请求发起时中止上一个未完成请求（AbortController）。
- 结果与输入必须一一对应：请求携带 `requestId`，响应回来后若 `requestId` 不是最新则丢弃。
- 语言未指定时需在同一次调用内完成「检测 + 翻译」，检测结果需回显到源语言区。
- 请求由浏览器直接发出（见 `FR-MODEL-02`），不得经过任何中间服务端。

#### FR-TEXT-02 字符上限与计数

**描述**：与竞品一致的输入长度约束与实时反馈。

**约束**：
- 单次文本翻译上限 **5000 字符**（按 Unicode 码点计数，而非字节）。
- 输入区下方常驻显示 `目前为 {N} 个字符（上限为 5,000 个字符）`。
- 当 `N / 5000 ≥ 0.9` 时计数变警告色；达到上限后禁止继续输入，并提示「已达到 5000 字符上限」。
- 超限粘贴时截断到 5000 字符并保留提示，不得静默丢弃。

#### FR-TEXT-03 清除原文

**约束**：
- 输入非空时显示「清除原文」按钮。
- 点击后：清空输入、清空结果、焦点回到输入框、计数归零。
- 清除动作**不**删除历史记录（历史是独立写入的）。

#### FR-TEXT-04 译文分段与复制

**约束**：
- 译文按段落/句子切分渲染，每段可独立悬停高亮（便于与原文对照）。
- 复制（`FR-ACT-01`）必须复制**纯文本**：不含 Markdown 标记、不含分段换行以外的多余空白。
- 复制成功后在按钮附近显示「译文已复制」提示，**2s 后自动消失**。

#### FR-TEXT-05 失败重试

**约束**：
- 错误分类：网络错误、鉴权错误（Key 无效/缺失）、限流（429）、内容被拒、模型超时。
- 每类错误必须给出可操作提示，禁止只显示「出错了」。
  - 鉴权错误 → 引导进入设置页配置对应服务商 Key。
  - 限流 → 显示「请求过于频繁，请稍后重试」，并禁用按钮至冷却结束。
  - 超时 → 提供「重试」按钮。
- 请求失败时必须保留原文与上一次成功的结果（如有），不得清空。

### 5.2 语言选择（P0/P1）

#### FR-LANG-01 源语言自动检测

**约束**：
- 源语言默认值为「检测语言」，此时目标语言**不允许**也为「检测语言」。
- 检测成功后，源语言 chip 文案变为 `{语言名} - 检测到的语言`。
- 检测置信度低于阈值时仍按最高置信度展示，但在 tooltip 中标注低置信度。

#### FR-LANG-02 语言列表

**约束**：
- 一期至少支持：中文（简体）、中文（繁体）、英语、日语、韩语、法语、德语、西班牙语、俄语、葡萄牙语、阿拉伯语、泰语。
- 列表顶部有**搜索框**，可输入中文名、英文名或语言代码过滤。
- 列表需支持键盘操作：`↑/↓` 移动、`Enter` 选中、`Esc` 关闭、输入字符自动聚焦搜索框。
- 列表过长时必须**虚拟滚动**，禁止一次性渲染全部 DOM 节点（性能红线，见第 8 节）。
- 搜索结果为空时显示空状态文案。

#### FR-LANG-03 常用语言快捷切换

**约束**：
- 源语言区、目标语言区各展示 3 个快捷 chip，外加「更多语言」入口。
- 快捷 chip 内容可配置，默认取用户最近使用频次最高的语言。
- 当前选中语言在 chip 上必须有明确的选中态（`aria-selected` 与视觉态一致）。

#### FR-LANG-04 交换语言（P1）

**约束**：
- 有输入内容时，「交换」需同时交换源语言、目标语言、原文与译文。
- 源语言为「检测语言」时按钮禁用。
- 交换后立即按新方向重新翻译，不得等待用户再次输入。
- 快捷键 `Cmd/Ctrl + Shift + S`。

#### FR-LANG-05 同语言校验（P1）

**约束**：
- 源语言与目标语言不可为同一种语言。
- 用户选择冲突语言时，自动把另一侧切换为「上次使用的不同语言」，并给出轻提示，不得直接报错阻断。

### 5.3 模型与接入（P0/P1/P2）

#### FR-MODEL-01 用户自带接入（BYOK）（P0）

**描述**：用户手动填写 `Endpoint`、`Model`、`API Key` 三者即可开始翻译，无需任何服务端配置。

**约束**：
- 设置页必须提供三个可编辑字段：`Endpoint`（Base URL）、`Model`（模型 ID）、`API Key`。
- 必须提供**预设模板**降低填写成本（OpenAI / Anthropic / Gemini / DeepSeek / OpenRouter / Ollama / 自定义），选择预设后自动填充 Endpoint 与常见模型，仅需补 Key。
- 允许用户**自定义 Endpoint**，用于兼容 OpenAI 协议的第三方网关与自建服务（`openaiCompatible` 适配器）。
- 允许用户保存**多套连接配置**并按名称切换。
- API Key 的存储与安全约束见 `FR-MODEL-06`。
- 必须区分**文本模型**与**多模态（视觉）模型**两类能力，能力矩阵在设置页可见：
  - 文本翻译：任一所配置的文本模型。
  - 图片翻译：仅具备视觉能力的模型（如 GPT-4o 系列、Claude 3.5+ 系列、Gemini 系列、LLaVA / Qwen-VL 等本地视觉模型）。
- 未配置任何连接时，应用必须可启动并引导用户进入设置页，不得白屏。

#### FR-MODEL-02 浏览器直连与 CORS 兼容矩阵（P0）

**描述**：请求由浏览器直接发往用户填写的 Endpoint。端点的 CORS 支持程度决定可用性。

**实测结论**（2026-10-02，以 `Origin` 发起预检/真实请求验证）：

| 服务商 | 预检通过 | 直连可行 | 备注 |
| --- | --- | --- | --- |
| OpenAI (`api.openai.com`) | ✅ `access-control-allow-origin` 回显 Origin | ✅ | 需注意官方策略可能调整 |
| Anthropic (`api.anthropic.com`) | ✅ | ✅ | 必须同时满足两个条件，缺一不可：<br>1) 请求头 `anthropic-dangerous-direct-browser-access: true`<br>2) SDK 构造项 `dangerouslyAllowBrowser: true`（否则 SDK 在构造时直接抛错） |
| Gemini (`generativelanguage.googleapis.com`) | ✅ 回显 Origin | ✅ | 预检已放行 `content-type` 与 `x-goog-api-key` |
| OpenRouter (`openrouter.ai`) | ✅ `access-control-allow-origin: *` | ✅ | 直连体验最稳定 |
| Ollama（本地） | ✅ | ✅ | 启动必须带 `OLLAMA_ORIGINS`，否则浏览器请求被拒 |
| 其他 OpenAI 兼容网关 | ⚠️ 由网关决定 | ⚠️ | 不可预判，须通过 `FR-MODEL-03` 连接测试验证 |

**约束**：
- 选型必须区分「已验证可直连」与「需用户自测」的服务商，在 UI 上用不同标识呈现。
- Anthropic 适配器必须显式传入 `dangerouslyAllowBrowser: true` 与 `anthropic-dangerous-direct-browser-access: true`，并将其标注为**官方设计如此**，而非绕过的 hack。
- 必须支持**流式输出**（SSE）。若某端点不支持流式，需降级为一次性返回并明确提示。
- 出现 CORS 失败时，浏览器只会给出「Failed to fetch / TypeError」，无法读取具体原因。因此错误提示必须**主动给出排查清单**，禁止只显示原始报错（见 `FR-MODEL-03`）。
- 请求不得携带任何平台方密钥；`Authorization` 仅携带用户自己填写的 Key。

#### FR-MODEL-03 连接测试与错误诊断（P0）

**约束**：
- 设置页必须提供「测试连接」按钮，发送一次最小请求（如 `max_tokens` 极小）验证 Endpoint / Model / Key 三者可用。
- 测试需在 **10s** 内返回明确结论：成功（含模型回显与延迟）/ 失败（含归因）。
- 失败归因至少覆盖：DNS 解析失败、网络不可达、CORS 被拒、401 鉴权失败、403 权限不足、404 模型或路径不存在、429 限流、5xx 服务端错误、响应格式不符合预期。
- 对 CORS 这类浏览器不暴露细节的失败，需提示固定排查项：
  1. Endpoint 是否写错或缺少 `/v1` 等路径；
  2. 该服务商是否允许浏览器直连（对照 `FR-MODEL-02` 矩阵）；
  3. Ollama 是否设置了 `OLLAMA_ORIGINS`；
  4. 是否为企业网络/代理拦截。
- 「测试连接」结果需显示原始状态码与响应体片段（Key 与敏感字段必须脱敏）。
- 未通过测试的配置**允许保存但不允许作为当前模型**，避免用户带着坏配置去翻译。

#### FR-MODEL-04 模型档位（P1）

**约束**：
- 参考竞品，提供两档语义：
  - **高级**：质量优先，走用户配置中能力最强的连接。
  - **快速**：延迟/成本优先，走轻量连接。
- 档位在用户已配置的多套连接中映射，未配置对应档位时给出提示而非静默替换。
- 档位选择需**持久化**（localStorage），刷新后保持。
- 界面需说明当前档位使用的具体 Endpoint 与模型名，避免黑盒。

#### FR-MODEL-05 风格与提示词（P2）

**约束**：
- 提供预设风格：直译、意译、正式、口语、技术文档。
- 支持用户自定义附加指令，长度上限 500 字符。
- 自定义指令只能拼装到用户消息侧，禁止覆盖系统级安全约束。

#### FR-MODEL-06 密钥本地存储与安全（P0）

**约束**：
- API Key **只存浏览器**（IndexedDB / localStorage），禁止发送到除用户配置的 Endpoint 之外的任何地址。
- 设置页必须提供「明文显示 / 掩码」切换，密钥在 UI 上默认掩码展示。
- 必须提供「清除所有密钥」一键操作，并二次确认。
- 必须在设置页明确风险提示：本项目采用 BYOK 直连，密钥保存在浏览器本地，请勿在公共设备上保存密钥。

- 日志与错误上报中一律不得出现密钥（见第 6 章隐私要求）。

### 5.7 图片翻译（P1）

#### FR-IMG-01 上传（P1）

**约束**：
- 支持三种入口：拖放、选择文件、粘贴剪贴板图片。
- 支持格式：`.jpg`、`.jpeg`、`.png`、`.webp`；拒绝其他格式并明确提示。
- 单文件上限 10MB，超限拒绝并提示。
- 拖放区域需有明确的拖入高亮态与非法文件态。

#### FR-IMG-02 识别与展示（P1）

**描述**：图片中的文字识别与翻译，**统一由多模态大模型一次调用完成**，不引入独立 OCR 引擎。

**约束**：
- 流程：图片 → 多模态模型（同时完成文字识别与翻译）→ 结构化结果渲染。
- 模型必须返回**结构化输出**：`[{ 原文, 译文, 边界框或区域顺序 }]`，禁止仅返回整段自由文本。
- 必须调用具备视觉能力的模型；当前配置的模型不支持图片输入时，需在调用前拦截并明确提示「当前模型不支持图片翻译，请切换到多模态模型」。
- 结果视图需支持「原文 / 译文 / 对照」三种模式切换；支持区域列表与图片叠加定位联动。
- 模型标注为不确定的识别区域需有视觉区分，不得假装高置信。
- 单张图片在调用前需压缩至模型输入上限内（最长边 ≤ 2048px，体积 ≤ 4MB）；压缩需保持文字可读，禁止降采样到无法识别。
- 处理中必须显示进度，单张图片处理超过 30s 需提示可继续等待或取消。
- 结构化输出解析失败时必须降级：重试一次，仍失败则展示原始模型文本并提示解析异常。

### 5.9 网站翻译（P2 / P1）

#### FR-WEB-02 URL 校验（P1）

**约束**：

## 7. 技术架构

### 7.1 架构决策：纯前端 SPA + BYOK 直连

**结论**：可行。项目**不需要自建服务端**，也不需要 Workers 作为默认方案。产物为纯静态资源。

技术路径：

1. **构建形态**：启用 TanStack Start 的 SPA 模式，通过 `tanstackStart({ spa: { enabled: true } })` 启用。构建时仅预渲染应用外壳（`_shell.html`），路由在客户端接管，**不产生任何服务端函数运行时**。
2. **模型调用**：浏览器直接 `fetch` 用户配置的 Endpoint，密钥从本地存储读取，全程不经过任何中间服务器。
3. **适配层**：沿用 `@tanstack/ai` 的 provider 适配器；其 ESM 产物不包含 `node:` 内置模块依赖，可在浏览器中直接运行（已核验 `ai-openai` / `ai-anthropic` / `ai-gemini` 的 `dist/esm`）。
4. **部署**：任意静态托管（Vercel 静态 / Cloudflare Pages / GitHub Pages / 对象存储）。需配置 SPA 回退：404 重写到 `_shell.html`。

**两个必须显式处理的落地点**：

- **Anthropic**：必须在 SDK 构造项传入 `dangerouslyAllowBrowser: true`，否则 SDK 在构造阶段直接抛错；同时请求头需带 `anthropic-dangerous-direct-browser-access: true`。二者缺一不可。该开关为官方提供，并非绕过限制。
- **OpenAI 系列**：`new OpenAI(...)` 同样会因浏览器环境抛错，需传入 `dangerouslyAllowBrowser: true`。`OpenAIClientConfig` 继承自 SDK 的 `ClientOptions`，可直接透传。

### 7.2 纯前端的能力边界（必须承认的限制）

| 能力 | 纯前端可行性 | 原因 |
| --- | --- | --- |
| 文本翻译（直连 LLM） | ✅ | 目标 Endpoint 支持 CORS 即可 |
| 图片翻译 | ✅ | 图片以 base64 随请求体发送，无额外跨域 |
| 文档翻译 | ✅ | 解析与生成均可在浏览器完成（zip / canvas 等） |
| 历史与收藏 | ✅ | IndexedDB，纯本地 |
| TTS | ✅ | `SpeechSynthesis` 浏览器原生 |
| **网站翻译（抓取第三方网页）** | ❌ **被限制** | 浏览器**无法**绕过目标站的 CORS 去读取任意网页。这是浏览器安全模型，不是实现问题 |
| 保护密钥不被用户看到 | ❌ 不适用 | BYOK 模式下密钥本就是用户自己的，无需保护 |

> 网站翻译在纯前端下**只能做「允许跨域」的站点**，覆盖率低。若必须做成通用能力，见 `7.3` 的 Workers 兜底。

### 7.3 Workers 兜底方案（按需，非默认）

仅在用户确实需要通用网站翻译时启用，作为**可选增强**，不得成为应用运行的前置条件。

**约束**：
- Workers 只做一件事：**代抓目标网页并附加 CORS 响应头**，然后把 HTML 返回给浏览器。
- Workers **不得**接触模型 API Key，**不得**代理模型请求。翻译仍由浏览器直连完成。
- Workers **不得**记录、缓存或落盘被抓取页面的正文内容；仅允许记录请求计数与耗时等元数据。
- 同一部署实例的 Workers 只服务该实例的用户，不做多租户共享抓取缓存。
- 提供「未配置 Workers 时自动禁用网站翻译入口」的降级逻辑；已配置时也需在 UI 标注该请求经过中继。
- 部署形态建议：Cloudflare Pages + Functions（同一仓库，`functions/` 目录），配置成本最低。

**若未来仍想彻底摆脱浏览器 CORS 依赖**，可升级为「Workers 代理模型请求」，但这会重新引入密钥托管问题，与 `2.4` 非目标冲突，**当前不采纳**。

### 7.4 技术约束

- 技术栈：TanStack Start（SPA 模式）+ TanStack Router + TanStack Store + Tailwind CSS。
- AI 调用统一经 `@tanstack/ai` 与其 provider 适配层（anthropic / openai / gemini / ollama）。
- 图片翻译使用多模态模型的视觉输入能力，不引入独立 OCR SDK。
- **无服务端密钥**：不得读取 `process.env` 中的任何模型密钥，不得把密钥写入构建产物。
- 持久化仅使用浏览器 IndexedDB / localStorage，不引入服务端数据库与用户账号体系。
- 状态管理：短生命周期用组件状态，跨路由共享用 TanStack Store，本地异步数据用 TanStack Query。
- 数据结构：高频查找场景（语言检索、历史搜索）禁止裸线性扫描，需使用 Trie / 索引或虚拟滚动优化，见第 8 节。

## 8. 性能与复杂度约束

1. **语言列表**：语言数量为常数级但选项多，禁止每次输入全量 `filter` 渲染；需建立名称→索引的检索结构（如前缀 Trie 或预建小写索引），输入过滤为 `O(前缀长度)` 级别查询。
2. **翻译记忆查询**：禁止在历史数组上做 `O(n)` 全量比对；使用哈希索引（原文 + 语言对 → 记录）实现 `O(1)` 命中。
3. **列表渲染**：历史记录、语言列表、图片翻译区域结果均需虚拟滚动，任何时刻 DOM 节点数量上限 200。
4. **并发**：同一时刻仅允许一个进行中的翻译请求；新请求必须中止旧请求。
5. **缓存**：语言列表、模型列表等静态数据进程内缓存，避免重复拉取。

## 11. 风险与开放问题

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 模型输出格式不稳定，难以稳定分段 | 分段渲染不可靠 | 约定结构化输出（JSON 分段），失败时降级为整段文本 |
| 多模态模型对图片文字的定位精度不稳定 | 区域对照错位 | 以「区域顺序」为主、边界框为辅；解析失败时降级为纯文本列表，不硬渲染错位框 |
| 多模态模型调用成本高于文本模型 | 图片翻译费用高 | 图片调用前压缩尺寸、限制单次图片数量、在设置页展示估算消耗 |
| 大文档翻译成本高 | 费用不可控 | 分块 + 增量翻译 + 预算上限提示 |
| **服务商随时可能收紧 CORS 策略** | 浏览器直连突然失效 | 连接测试可在 10s 内暴露问题；保留 Workers 中继作为可选兜底；在 `FR-MODEL-02` 矩阵中标注实测日期 |
| 用户把适配 OpenAI 协议的私有网关填入 | 网关行为不可预判 | 依靠「测试连接」把关，未通过不设为当前模型 |
| 浏览器扩展或恶意脚本可读取本地存储的密钥 | 密钥泄露 | 明确提示勿在公共设备保存；提供一键清除；导出默认排除密钥 |
| 网站抓取易被反爬 | 功能不稳定 | 明确降级策略与失败提示，不承诺成功率；纯前端下站点覆盖率天然受限 |
| TTS 依赖浏览器能力 | 跨端不一致 | 按钮按能力启用/禁用，并说明原因 |
| 本地存储被浏览器清理 | 历史与配置丢失 | 提供导入/导出 JSON；在清空与导出入口明示本地存储风险 |

**已决策**：

1. 一期**不做**账号体系与云同步，历史与收藏仅存本地，通过导入/导出 JSON 支持用户自行备份迁移。
2. 图片翻译**使用多模态大模型**完成识别与翻译，不引入独立 OCR 引擎。
3. 产品定位为**单机单用户个人工具**，不涉及团队场景；不做成员管理、共享语料与配额分配，因此也不引入面向团队的用量统计与配额管理。
4. 架构为**纯前端 SPA + BYOK 浏览器直连**，无服务端、无密钥托管；Workers 仅作为网站翻译的可选兜底，不是默认依赖。

**待确认问题**：

1. 暂无。
