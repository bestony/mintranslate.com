## 1. 文档说明

### 1.1 目的

本文档定义 MinTranslate 的产品定位、功能范围、优先级与功能约束，作为设计、开发与验收的唯一依据。

### 1.2 需求来源

本节需求来自对竞品 **Google 翻译**（`https://translate.google.com`）的真实操作体验与逐项拆解，实测时间：2026-10-02。

实测覆盖的操作路径：

| 序号 | 操作 | 观察结果 |
| --- | --- | --- |
| 1 | 打开默认页（`sl=auto&tl=zh-CN&op=translate`） | 进入「文本翻译」，源语言为「检测语言」，目标语言为「中文（简体）」 |
| 2 | 输入英文长句 | 自动识别为「英语 - 检测到的语言」，结果流式返回，按句拆分为多行 |
| 3 | 打开设置菜单 | 语速设置为「正常 / 慢 / 更慢」，每档带「测试」播放按钮 |
| 4 | 展开「更多源语言」 | 弹出带搜索框的语言列表，选项按中文拼音排序，共 200+ 项 |
| 5 | 依次进入图片 / 文档 / 网站翻译 | 各自的独立上传与输入形态；网站翻译对非法输入提示「输入内容必须是格式正确的非空网址」 |
| 6 | 点击交换源/目标语言 | 源、目标语言互换，原文与译文同时互换，页内文案随之变化 |
| 7 | 输入中文并切换目标语言为英语 | 目标语言为英语时，原输入区额外出现「文字翻译模型」「输入工具」入口 |
| 8 | 打开「文字翻译模型」菜单 | 提供「高级（借助 Gemini，准确性更高）」与「经典」两个模型档位 |
| 9 | 打开手写输入面板 | 提供画板、标点符号快捷插入、「多语种」标识 |
| 10 | 点击「保存翻译」 | 弹出「登录即可查看已保存的译文」模态框，未登录不可保存 |
| 11 | 点击「复制译文」 | 提示「译文已复制」 |
| 12 | 点击「分享此译文」 | 提供「电子邮件」（`mailto:`，正文含译文）与「X」（`twitter.com/intent/tweet`） |
| 13 | 点击「请对此翻译评分」 | 展开「翻译质量很棒 / 翻译质量很差 / 提出修改建议」，修改建议可进入可编辑替换文本界面 |
| 14 | 访问「历史记录」 | 未登录被重定向到 Google 登录页 |

## 2. 产品定位

### 2.1 一句话定义

MinTranslate 是一个**面向个人与团队的自托管 AI 翻译工作台**：以文本翻译为核心，逐步覆盖图片、文档与网站翻译，支持多模型（OpenAI / Anthropic / Gemini / Ollama）与本地部署。

### 2.2 目标用户

| 用户画像 | 核心诉求 |
| --- | --- |
| 个人开发者 / 技术用户 | 阅读英文文档、报错、论文，希望结果留在本地、可换模型 |
| 内容与运营人员 | 批量翻译文案、文档，需要术语一致、可保存与复用 |
| 跨境业务团队 | 需要私有化配额与成本控制，不愿把内容发给第三方 |

### 2.3 与竞品的差异化

1. **模型可替换**：不绑定单一厂商，用户自带 Key 或走本地 Ollama。
2. **数据可控**：历史记录与语料默认存本地 / 自建库，不强制登录。
3. **可编程**：提供 API 与 MCP 接入，方便被其他 Agent 调用。
4. **术语表与翻译记忆**：把「一致性」作为一等公民，而非附加功能。

### 2.4 非目标（本阶段明确不做）

- 不做语音同传 / 实时会议字幕。
- 不做浏览器的整站代理式翻译插件（网站翻译仅做「按 URL 抓取 + 译文并排展示」）。
- 不做社区众包式翻译质量共建。
- 不承诺覆盖 Google 的全部 200+ 语种，一期聚焦下列 12 种语言（见 `FR-LANG-02`）。

## 5. 功能约束详情

### 5.1 文本翻译（P0）

#### FR-TEXT-01 实时翻译

**描述**：用户输入文本后自动翻译，无需手动点击按钮。

**约束**：
- 触发方式：输入停止后 **600ms 防抖**触发；用户按 `Cmd/Ctrl + Enter` 立即触发。
- 输入为空或仅空白字符时，不发起请求，结果区恢复空态。
- 结果必须**流式渲染**：请求开始后立即展示「翻译中」占位，首个 token 到达时间目标 < 1.5s（P95，正常网络）。
- 同一输入的重复请求必须可取消：新请求发起时中止上一个未完成请求（AbortController）。
- 结果与输入必须一一对应：请求携带 `requestId`，响应回来后若 `requestId` 不是最新则丢弃。
- 语言未指定时由服务端同时完成「检测 + 翻译」，检测结果需回显到源语言区。

#### FR-TEXT-02 字符上限与计数

**描述**：与竞品一致的输入长度约束与实时反馈。

**约束**：
- 单次文本翻译上限 **5000 字符**（按 Unicode 码点计数，而非字节）。
- 输入区下方常驻显示 `目前为 {N} 个字符（上限为 5,000 个字符）`。
- 当 `N / 5000 ≥ 0.9` 时计数变警告色；达到上限后禁止继续输入，并提示「已达到 5000 字符上限」。
- 超限粘贴时截断到 5000 字符并保留提示，不得静默丢弃。

#### FR-TEXT-03 清除原文

**约束**：
- 输入非空时显示「清除原文」按钮。
- 点击后：清空输入、清空结果、焦点回到输入框、计数归零。
- 清除动作**不**删除历史记录（历史是独立写入的）。

#### FR-TEXT-04 译文分段与复制

**约束**：
- 译文按段落/句子切分渲染，每段可独立悬停高亮（便于与原文对照）。
- 复制（`FR-ACT-01`）必须复制**纯文本**：不含 Markdown 标记、不含分段换行以外的多余空白。
- 复制成功后在按钮附近显示「译文已复制」提示，**2s 后自动消失**。

#### FR-TEXT-05 失败重试

**约束**：
- 错误分类：网络错误、鉴权错误（Key 无效/缺失）、限流（429）、内容被拒、模型超时。
- 每类错误必须给出可操作提示，禁止只显示「出错了」。
  - 鉴权错误 → 引导进入设置页配置对应服务商 Key。
  - 限流 → 显示「请求过于频繁，请稍后重试」，并禁用按钮至冷却结束。
  - 超时 → 提供「重试」按钮。
- 请求失败时必须保留原文与上一次成功的结果（如有），不得清空。

### 5.2 语言选择（P0/P1）

#### FR-LANG-01 源语言自动检测

**约束**：
- 源语言默认值为「检测语言」，此时目标语言**不允许**也为「检测语言」。
- 检测成功后，源语言 chip 文案变为 `{语言名} - 检测到的语言`。
- 检测置信度低于阈值时仍按最高置信度展示，但在 tooltip 中标注低置信度。

#### FR-LANG-02 语言列表

**约束**：
- 一期至少支持：中文（简体）、中文（繁体）、英语、日语、韩语、法语、德语、西班牙语、俄语、葡萄牙语、阿拉伯语、泰语。
- 列表顶部有**搜索框**，可输入中文名、英文名或语言代码过滤。
- 列表需支持键盘操作：`↑/↓` 移动、`Enter` 选中、`Esc` 关闭、输入字符自动聚焦搜索框。
- 列表过长时必须**虚拟滚动**，禁止一次性渲染全部 DOM 节点（性能红线，见第 8 节）。
- 搜索结果为空时显示空状态文案。

#### FR-LANG-03 常用语言快捷切换

**约束**：
- 源语言区、目标语言区各展示 3 个快捷 chip，外加「更多语言」入口。
- 快捷 chip 内容可配置，默认取用户最近使用频次最高的语言。
- 当前选中语言在 chip 上必须有明确的选中态（`aria-selected` 与视觉态一致）。

#### FR-LANG-04 交换语言（P1）

**约束**：
- 有输入内容时，「交换」需同时交换源语言、目标语言、原文与译文。
- 源语言为「检测语言」时按钮禁用。
- 交换后立即按新方向重新翻译，不得等待用户再次输入。
- 快捷键 `Cmd/Ctrl + Shift + S`。

#### FR-LANG-05 同语言校验（P1）

**约束**：
- 源语言与目标语言不可为同一种语言。
- 用户选择冲突语言时，自动把另一侧切换为「上次使用的不同语言」，并给出轻提示，不得直接报错阻断。

### 5.3 模型（P0/P1/P2）

#### FR-MODEL-01 多模型接入

**约束**：
- 必须支持：OpenAI、Anthropic、Google Gemini、Ollama（本地）。
- Key 一律通过**服务端环境变量**持有，禁止下发到浏览器（`VITE_` 前缀变量不得承载密钥）。
- 模型调用统一走服务端函数（TanStack Start server function），浏览器不直连第三方 API。
- 未配置任何服务商 Key 时，应用必须可启动并给出明确的配置引导，不得白屏。

#### FR-MODEL-02 模型档位（P1）

**约束**：
- 参考竞品，提供两档语义：
  - **高级**：质量优先，走能力最强的模型。
  - **快速**：延迟/成本优先，走轻量模型。
- 档位选择需**持久化**（localStorage），刷新后保持。
- 界面需说明当前档位使用的具体模型名，避免黑盒。

#### FR-MODEL-03 风格与提示词（P2）

**约束**：
- 提供预设风格：直译、意译、正式、口语、技术文档。
- 支持用户自定义附加指令，长度上限 500 字符。
- 自定义指令必须经过服务端拼装，禁止让用户直接覆盖系统级安全约束。

### 5.4 语料资产（P1/P2）

#### FR-TERM-01 术语表

**约束**：
- 用户可维护 `源词 → 目标词` 二元组，按语言对分组。
- 命中术语时**强制**使用指定译法，优先级高于模型自由发挥。
- 术语注入模型上下文时需限制条数（单次 ≤ 50 条），避免超出上下文窗口。
- 需展示哪些术语在本次翻译中命中。

#### FR-TERM-02 翻译记忆（P2）

**约束**：
- 完全相同的原文 + 相同语言对 → 直接返回缓存译文，不调用模型。
- 相似度 ≥ 阈值的既有译文可作为参考注入。
- 缓存需带版本号，术语表变更后相关缓存失效。

---

### 5.5 历史与收藏

#### FR-HIST-01 历史记录（P0）

**约束**：
- **免登录可用**，一期存于浏览器 IndexedDB。
- 每条记录字段至少包含：原文、译文、源语言、目标语言、使用模型、时间戳。
- 相同原文 + 相同语言对重复翻译时**更新**而非新增（去重）。
- 单条记录原文上限 5000 字符；本地保留上限默认 1000 条，超出按时间淘汰。
- 必须提供「清空历史」，且二次确认。

#### FR-HIST-02 收藏（P1）

**约束**：
- 「保存翻译」标记收藏，收藏项不参与自动淘汰。
- 收藏与历史在同一列表视图中可筛选。
- 需要账号体系时，登录后再做云端同步；未登录状态功能不得降级为不可用。

#### FR-HIST-03 搜索与批量管理（P1）

**约束**：
- 支持按原文、译文关键字搜索。
- 支持按语言对、时间范围过滤。
- 支持批量删除与批量导出（JSON / CSV）。

### 5.6 输出动作

#### FR-ACT-01 复制译文（P0）

**约束**：
- 复制内容为纯文本译文全文。
- 浏览器不支持剪贴板 API 时需降级为选中 + 提示手动复制，禁止静默失败。

#### FR-ACT-02 TTS 与语速（P2）

**约束**：
- 「听取原文」「听取译文」分别调用浏览器 `SpeechSynthesis`；不支持时按钮禁用并说明原因。
- 语速提供三档：正常 / 慢 / 更慢，每档带「测试」按钮。
- 语速设置需持久化。

#### FR-ACT-03 分享（P2）

**约束**：
- 分享链接必须能**还原完整状态**（`sl`、`tl`、`text`、`op` 参数），打开即重现翻译结果。
- 分享链接长度受 URL 限制时，超出阈值改为分享短链或提示长度超限。
- 邮件分享正文需 URL Encode 正确编码。

#### FR-ACT-04 二次检索（P2）

**约束**：
- 「使用搜索引擎」跳转时需对译文进行 URL 编码，且在新标签打开。

#### FR-ACT-05 质量反馈（P2）

**约束**：
- 提供「质量很棒 / 质量很差 / 提出修改建议」三级反馈。
- 「修改建议」进入可编辑界面，提交后记录到本地反馈表；未登录不上传。
- 反馈数据不包含用户身份信息。

---

### 5.7 图片翻译（P1）

#### FR-IMG-01 上传（P1）

**约束**：
- 支持三种入口：拖放、选择文件、粘贴剪贴板图片。
- 支持格式：`.jpg`、`.jpeg`、`.png`、`.webp`；拒绝其他格式并明确提示。
- 单文件上限 10MB，超限拒绝并提示。
- 拖放区域需有明确的拖入高亮态与非法文件态。

#### FR-IMG-02 识别与展示（P1）

**约束**：
- 流程：OCR 抽文字 → 翻译 → 叠加展示。
- 结果视图需支持「原文 / 译文 / 对照」三种模式切换。
- 低置信度 OCR 区域需有视觉区分。
- 处理中必须显示进度，单张图片处理超过 30s 需提示可继续等待或取消。

---

### 5.8 文档翻译（P1/P2）

#### FR-DOC-01 上传与下载（P1）

**约束**：
- 支持格式：`.docx`、`.pdf`、`.pptx`、`.xlsx`；其余格式明确拒绝。
- 单文件上限 20MB。
- 输出必须尽量**保留原排版**；无法保留时需在下发前明确告知用户。
- 下载文件名格式：`{原文件名}.{目标语言}.{扩展名}`。

#### FR-DOC-02 异步任务（P2）

**约束**：
- 超过阈值（默认 50 页或 2MB）转异步任务，避免请求超时。
- 任务需有状态机：排队 → 处理中 → 成功 / 失败 / 取消。
- 支持断点续传式的分块翻译，分块边界必须落在段落/句子上，禁止切碎句子。

---

### 5.9 网站翻译（P2 / P1）

#### FR-WEB-02 URL 校验（P1）

**约束**：
- 必须拒绝空值和非法 URL，提示文案参照竞品语义：「输入内容必须是格式正确的非空网址」。
- 自动补全 `https://` 前缀；仅支持 `http` / `https` 协议。
- 拒绝内网地址与 `localhost`（SSRF 防护，见第 8 节）。

#### FR-WEB-01 整站翻译（P2）

**约束**：
- 抓取目标页正文，过滤脚本、样式与广告节点后再翻译。
- 结果以「原文 / 译文 / 对照」三模式呈现。
- 单页抓取超时 20s；超时给出明确失败提示。
- 需遵守 `robots.txt`，并在界面标注来源 URL 与抓取时间。

---

### 5.10 交互形态

#### FR-UX-01 状态与 URL 同步（P1）

**约束**：
- 参数约定：`sl`（源语言）、`tl`（目标语言）、`text`（原文）、`op`（模式：`translate` / `images` / `docs` / `websites`）。
- 状态变化需同步到 URL（`replaceState`，避免污染浏览器历史），直接打开链接可复原状态。
- `text` 参数需 URL Encode，长度超阈值时不写入 URL，仅保留内存状态。

#### FR-UX-02 响应式布局（P0）

**约束**：
- 桌面端：左右双栏（原文 / 译文）+ 左侧导航。
- 平板端：双栏收窄，导航折叠为图标。
- 移动端：单栏纵向堆叠，模式切换改为顶部 Tab。
- 断点需覆盖 375px、768px、1280px、1536px 四个宽度。
- 输入区与结果区需支持独立滚动，长文本不得撑破容器。

#### FR-UX-03 主题（P2）

**约束**：
- 提供浅色 / 深色切换，默认跟随系统 `prefers-color-scheme`。
- 首屏渲染前应用主题，避免闪烁（FOUC）。
- 主题选择持久化。

#### FR-UX-04 快捷键（P2）

**约束**：
- 至少实现：`Cmd/Ctrl + Enter` 立即翻译、`Cmd/Ctrl + Shift + S` 交换语言、`Esc` 关闭弹层。
- macOS 显示 `Cmd`，Windows/Linux 显示 `Ctrl`（按平台动态渲染）。

---

### 5.11 开放能力（P2）

#### FR-API-01 API / MCP

**约束**：
- 提供 `POST /api/translate`，入参 `{ text, source, target, model? }`，出参 `{ detectedSource, translation, requestId }`。
- 需支持 API Key 鉴权与速率限制。
- 提供 MCP 工具封装，便于其他 Agent 直接调用。

## 6. 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 首屏 LCP < 2.5s；输入到首 token < 1.5s（P95）；语言列表滚动 ≥ 55 FPS |
| 可用性 | 模型服务不可用时应用整体不崩溃，降级为可浏览历史 |
| 安全 | API Key 仅存服务端；网站翻译必须做 SSRF 防护；用户输入一律转义，防止 XSS |
| 隐私 | 默认不采集内容；历史默认仅存本地；日志脱敏，不打印原文全文与密钥 |
| 可访问性 | 交互元素具备可访问名称；弹层支持键盘操作与焦点陷阱；对比度符合 WCAG AA |
| 国际化 | UI 文案中英双语；语言名与代码的映射表集中维护 |
| 兼容性 | 最新版 Chrome / Safari / Edge / Firefox；移动端 Safari 与 Chrome |

## 7. 技术约束

- 技术栈：TanStack Start + TanStack Router + TanStack Store + Tailwind CSS。
- AI 调用统一经 `@tanstack/ai` 与其 provider 适配层（anthropic / openai / gemini / ollama）。
- 密钥经环境变量注入服务端，`VITE_` 前缀变量不得承载密钥。
- 状态管理：短生命周期用组件状态，跨路由共享用 TanStack Store，服务端数据用 TanStack Query。
- 数据结构：高频查找场景（语言检索、历史搜索）禁止裸线性扫描，需使用 Trie / 索引或虚拟滚动优化，见第 8 节。

---

## 8. 性能与复杂度约束

1. **语言列表**：语言数量为常数级但选项多，禁止每次输入全量 `filter` 渲染；需建立名称→索引的检索结构（如前缀 Trie 或预建小写索引），输入过滤为 `O(前缀长度)` 级别查询。
2. **翻译记忆查询**：禁止在历史数组上做 `O(n)` 全量比对；使用哈希索引（原文 + 语言对 → 记录）实现 `O(1)` 命中。
3. **列表渲染**：历史记录、语言列表、图片 OCR 区域均需虚拟滚动，任何时刻 DOM 节点数量上限 200。
4. **并发**：同一时刻仅允许一个进行中的翻译请求；新请求必须中止旧请求。
5. **缓存**：语言列表、模型列表等静态数据进程内缓存，避免重复拉取。

## 11. 风险与开放问题

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 模型输出格式不稳定，难以稳定分段 | 分段渲染不可靠 | 约定结构化输出（JSON 分段），失败时降级为整段文本 |
| 大文档翻译成本高 | 费用不可控 | 分块 + 增量翻译 + 预算上限提示 |
| 网站抓取易被反爬 | 功能不稳定 | 明确降级策略与失败提示，不承诺成功率 |
| TTS 依赖浏览器能力 | 跨端不一致 | 按钮按能力启用/禁用，并说明原因 |
